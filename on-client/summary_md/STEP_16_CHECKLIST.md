# 16단계 진행 상황 및 직접 확인 체크리스트

이 문서는 보안 Agent **「케셰브」**의 16단계 **「알림·빈 상태·오류·진단 정보 정리」**의 현재 코드 구현 현황과 사용자가 브라우저에서 직접 확인해야 할 검증 절차를 정리한 가이드입니다.

---

## 1. 현재 진행 상황 요약

| 항목 | 상태 | 설명 |
|---|:---:|---|
| **`renderStatus` 구현** | ✅ 완료 | 기기·세션(로딩/빈상태/오류), 주의 알림, 안전한 도움정보 표시 |
| **`도움정보 복사` 버튼** | ✅ 완료 | 정확한 버튼 이름 생성, 6대 안전 필드 선별 클립보드 복사 |
| **미지원 조치 안내** | ✅ 완료 | 15단계 상세 영역에 `<action> 미지원` 비활성 버튼 추가 |
| **문법 검사 (`check`)** | ✅ 완료 | `npm run check` (Node.js 문법 검사 통과) |
| **Git 상태** | ⏳ 대기 | 코드 구현 완료, 로컬 확인 후 커밋 및 제출 대기 중 |

---

## 2. 화면에서 직접 확인할 4가지 핵심 체크리스트

### [체크 1] 기기·세션의 "빈 상태"와 "실패 상태" 구분
* **확인 위치**: 브라우저 > **보호 현황** 탭 > **학생 상태·알림 표시** 영역
* **확인할 내용**:
  * [ ] **빈 목록일 때**: `등록된 기기가 없습니다`, `현재 연결 없음 (등록된 세션이 없습니다)` 안내 문구가 정상적으로 표시되는지 확인합니다.
  * [ ] **실패했을 때**: 에러 메시지와 함께 시간 초과 시 `(요청 시간 초과)`가 명확히 보이고, 빈 목록 안내와 시각적으로 엄격히 구분되는지 확인합니다.
  * [ ] **세션 범위 안내**: *"세션은 지금 검증된 연결 하나만 옵니다 (지난 세션 목록이 아닙니다)."* 문구가 포함되어 있는지 확인합니다.

### [체크 2] 수동 재시도 안내 및 자동 재요청 차단
* **확인할 내용**:
  * [ ] 실패 안내 아래에 *"다시 시도는 위쪽 다시 불러오기 버튼을 직접 누르세요. (자동으로 다시 요청하지 않습니다.)"* 안내 문구가 있는지 확인합니다.
  * [ ] 브라우저 개발자 도구(F12)의 **네트워크(Network)** 탭을 켰을 때, 프로그램이 백그라운드에서 임의로 요청을 반복(polling)하지 않는지 확인합니다.
  * [ ] 상단의 **"다시 불러오기"**를 눌러 성공했을 때 이전 실패 메시지가 깨끗하게 사라지는지 확인합니다.

### [체크 3] 주의 알림 (`notifications`) 표시
* **확인할 내용**:
  * [ ] 주의가 필요한 항목이 있으면 `[어느 자료(resource)] (보안 코드) 메시지` 형식으로 표시되는지 확인합니다.
  * [ ] 알림이 없는 정상 상태에서는 `주의할 알림이 없습니다` 문구가 명확히 뜨는지 확인합니다.

### [체크 4] 비밀 없는 도움정보 표시 및 「도움정보 복사」 버튼
* **확인할 내용**:
  * [ ] **6대 안전 필드만 표시**: `요청 ID`, `컴포넌트`, `버전`, `점검 시각`, `엔진 모드`, `엔진 코드` 6개 항목만 노출되는지 확인합니다.
  * [ ] **비밀정보 배제**: API 키, 토큰, 비밀번호 같은 민감 정보가 화면에 전혀 노출되지 않는지 확인합니다.
  * [ ] **정확한 버튼 이름**: 버튼 텍스트가 정확히 **`도움정보 복사`**로 되어 있는지 확인합니다.
  * [ ] **복사 동작**: 버튼을 클릭했을 때 클립보드에 해당 6개 안전 필드(JSON)가 복사되고, *"도움정보가 클립보드에 복사되었습니다."* 상태 문구가 나타나는지 확인합니다.

### [체크 5] 미지원 조치 비활성 버튼 (`unsupported_action`)
* **확인 위치**: 브라우저 > **보안 기록** 탭 > 사건 목록 중 하나의 **`<ID> 상세`** 카드
* **확인할 내용**:
  * [ ] 실제 목록처럼 `supportedActions`가 비어 있으면 조치 버튼이 일체 생성되지 않는지 확인합니다.
  * [ ] 테스트 데이터 등으로 미지원 조치 목록이 들어올 경우, 정확한 이름의 **`"<action> 미지원"`** **비활성 버튼(`disabled`)**과 *"조치 실행 연결은 준비 중입니다"* 안내가 뜨며, 클릭해도 서버로 어떠한 요청도 전송되지 않는지 확인합니다.

## 3. 브라우저 실행 및 테스트 방법

PowerShell에서 서버를 실행하고 브라우저를 엽니다:

```powershell
# 1. 프로젝트 폴더(on-client)로 이동
cd C:\Users\user\Desktop\ALEPH\git_folder\alekov-starter-0.2.11\on-client

# 2. 데모 서버 실행
npm run demo
```
*(※ 포트 충돌 시: `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo -Port 5190`)*

* **브라우저 접속 주소**: `http://127.0.0.1:5189` (또는 `5190`)
* **확인 화면**:
  1. **"보호 현황"** 탭의 아래쪽 **[학생 상태·알림 표시]**
  2. **"보안 기록"** 탭의 **[학생 구현 표시]** 내 상세 보기

## 4. 확인 완료 후 커밋 및 제출 명령어

체크리스트 확인이 끝나면 PowerShell에서 아래 명령어로 커밋 및 푸시 후 워크벤치/포털에서 **16단계**를 제출하시면 됩니다:

```powershell
# 1. 변경된 파일 스테이징
git add student/extension.mjs summary_md/ docs/

# 2. 커밋 생성
git commit -m "16단계: renderStatus 구현, 미지원 조치 비활성 안내 및 확인 체크리스트 추가"

# 3. 원격 저장소 푸시
git push origin master
```
