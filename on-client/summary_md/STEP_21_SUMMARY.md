# 21단계 작업 요약 (케셰브 보안 Agent)

이 문서는 보안 Agent **「케셰브」**의 21단계 **「학생용 실행 설명서와 시스템 구성도」**에서 구현한 문서화 작업과 핵심 보안 원칙을 정리한 작업 기록입니다. (공식 AI 심사 피드백 5대 항목 전원 반영 완료)

---

## 1. 전체 목표

다른 작업자가 실제 작업 위치와 검증된 실행 명령을 확인하며 프로젝트를 스스로 설치·실행·검증할 수 있도록 완전한 실행 설명서(Runbook)를 제공하고, 시스템의 핵심 구성요소와 데이터 흐름을 Mermaid 다이어그램 및 상세 설명 표로 투명하게 문서화합니다. 제공 코드와 학생 구현 영역을 명확히 구분하고, 실제 화면에 나타나는 실패 문구별 복구 절차 및 아직 확인되지 않은 항목을 정직하게 구분합니다.

* **작성 파일**: `docs/STUDENT_RUNBOOK.md` (학생 실행 설명서 개정판)
* **연계 문서**: `summary_md/STEP_21_SUMMARY.md` 및 `docs/summary_md/STEP_21_SUMMARY.md`

---

## 2. 심사 피드백 반영 및 핵심 개정 내용

### 1) 실행 절차 및 지원 버전 일치 (`run_instructions_match_source`, `support_scope_honest`)
* **지원 버전 엄격화**: `Node.js 20 이상`이라는 막연한 표현을 배제하고, `package.json`의 선언 버전인 **`Node.js 24.19.0` (실행 허용 범위: 22~24)**로 명확히 한정. 20, 21 버전은 미지원/미확인으로 분류.
* **작업 디렉토리 일반화**: 개인 PC의 절대 경로 하드코딩을 제거하고, 저장소 클론 위치 기준의 상대 경로(`cd on-client`) 및 일반적인 탐색 방법 안내.

### 2) 시스템 구성도와 실제 코드 흐름 일치 (`architecture_matches_source`)
* **요청 분기 및 모듈 역할 수정**:
  * `src/actions/sdp-action-engine.mjs`를 접근 판정 모듈이 아닌 **원천 보안 조치(prepare/execute/observation) 전용 모듈**로 명확히 재정의.
  * 일반 사용자·기기·앱 접속 판정·사건 기록 조회는 `src/engine.mjs`의 `readIdentity`, `readApps`, `decideAccess`, `readEvents`가 담당하는 실제 코드 흐름을 Mermaid 다이어그램과 표에 100% 일치시켜 반영.

### 3) 제공/학생 코드 경계 명확화 (`provided_student_boundary`)
* `.on-starter-manifest.json` 해시 대조를 통해 `student/engine-adapter.mjs`는 **제공 파일(어댑터 틀)**임을 명시.
* 학생이 작성하는 유일한 코드는 **`student/extension.mjs` (13~20단계 8대 UI 렌더링 함수)** 뿐임을 확립.

### 4) 실제 코드에 기반한 오류 점검 절차 (`failure_guide_matches_source`)
* `src/server.mjs`가 오류 발생 시 콘솔 로그를 남기지 않고 JSON 응답을 반환하는 실제 동작에 맞추어, "서버 콘솔 로그 확인" 문구를 완전 제거.
* 학생이 실제로 확인할 수 있는 **화면 오류 코드, 개발자 도구 Network 탭 응답 본문(`{ ok: false, error }`), 「도움정보」 탭의 `[진단 정보 복사]` 기능**과 직접 연결된 실질적 점검 절차 기술.

### 5) 실제 버튼 이름 및 탭 매트릭스 대조표 제공
* 화면의 실제 버튼(`[설치 패키지 조회]`, `[패키지 조회 취소]`, `[조치 준비]`, `[실행 승인]`, `[원천 결과만 재조회]`, `[진단 정보 복사]`)과 HTML id 및 요소 속성 대조표 완비.
