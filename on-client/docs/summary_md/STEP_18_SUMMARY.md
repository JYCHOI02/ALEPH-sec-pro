# 18단계 작업 요약 (케셰브 보안 Agent)

이 문서는 보안 Agent **「케셰브」**의 18단계 **「근거에 연결된 AI 보안 이벤트 설명」**에서 구현한 기능과 핵심 보안 원칙을 정리한 작업 기록입니다.

---

## 1. 전체 목표

선택한 보안 이벤트(`event`)의 근거(`evidence`), 규칙(`rules`), 현재 상태(`state`)를 AI 설명 요약(`explanation.data.summary`)과 연결하여 표시하고, 근거 없는 설명이나 근거 불일치, 이미 실행했다고 주장하는 거짓 설명(`executed: true`)을 엄격히 거부합니다. 또한 `unknown` 상태를 정상이나 안전으로 왜곡하지 않고, 조치 제안은 자동 실행되지 않는 안내와 함께 사람 확인이 필요함을 명시합니다.

* **수정 파일**: `student/extension.mjs` 내 `renderExplanation` (AI 사건 설명 표시 영역)
* **표시 위치**: "보안 기록" 탭의 **[학생 AI 사건 설명]** 영역 (`renderExplanation`)

---

## 2. 구현한 핵심 기능

### 1) 설명 실패(`error`)의 안전한 표시
* **`event`가 `null`이어도 안전한 렌더링**: 사건이 선택되지 않은 상태에서 오류가 발생해도 예외를 던지지 않고 안전하게 에러 코드(`error.code`)와 메시지(`error.message`)를 표시합니다.
* **기록 불변성 보장**: *"기록은 그대로 유지됩니다. AI 연결이나 응답 문제는 과제 실패로 처리되지 않습니다."* 문구를 명시하여 원본 보안 기록이 훼손되지 않음을 사용자에게 보장합니다.
* **성공 표식 미부여**: 오류 화면에는 `data-student-explanation-event` 속성을 절대 부여하지 않습니다.

### 2) 설명 요청 중(`loading`) 및 기록 미선택(`event: null`) 상태 분기
* **요청 중 (`loading`)**: `설명 생성 중… (loading)` 상태 라벨과 함께, 선택된 사건 ID를 표시하며 AI 설명을 불러오는 중임을 안내합니다.
* **기록 미선택 (`!event`)**: `대기 중 (idle)` 상태 라벨과 함께 *"보안 기록에서 기록을 먼저 고르세요. 사건을 선택해야 AI 설명을 요청할 수 있습니다."* 안내를 표시합니다.

### 3) 엄격한 검증 및 허위/왜곡 설명 거부 (3중 검증)
AI 응답 상태가 `ok`이더라도 다음과 같은 결함이 있으면 설명을 수용하지 않고 즉시 거부하며, `data-student-explanation-event` 속성을 부여하지 않습니다:
1. **근거 부족 검사 (`insufficient_evidence`)**:
   * 사건에 근거(`evidence`)가 없거나 빈 배열인 경우: *"근거 부족으로 설명을 처리할 수 없습니다(근거 부족·입력 오류). 사건에 확인된 근거가 없습니다."* 안내와 함께 거부합니다.
2. **거짓 실행 주장 거부 (`executed_output_rejected`)**:
   * AI 응답 데이터에 `executed: true`가 포함된 경우: *"AI가 이미 실행했다고 답한 설명은 쓸 수 없습니다. 제안은 자동 실행되지 않으며 사람 확인이 필요합니다."* 안내와 함께 거부합니다.
3. **근거 불일치 검사 (`wrong_event_rejected`)**:
   * AI가 인용한 근거 ID(`evidenceIds`) 중 실제 사건 기록(`event.evidence`)에 존재하지 않는 ID가 포함된 경우: *"근거 불일치: AI 설명의 근거 ID가 사건 기록과 일치하지 않아 해당 설명을 쓸 수 없습니다."* 안내와 함께 거부하고 내용을 지어내지 않습니다.

### 4) 성공한 설명의 근거·규칙·상태 연결 렌더링
모든 검증을 통과한 경우에만 최상위 컨테이너에 **`data-student-explanation-event="<event.id>"`** 속성을 부여하고 다음 항목들을 명확히 연결하여 표시합니다:
* **상태 및 제목**: `설명 완료 (ok)` 상태 라벨, `AI 설명 (참고용)` 제목, 사건 ID(`사건 ID: <event.id>`), AI 요약 본문(`data.summary`)과 참고용 안내 문구.
* **인용한 근거 ID 및 본문 (`evidence_binding`)**: AI가 인용한 `evidenceIds`마다 사건의 `event.evidence`에서 일치하는 ID를 찾아 **`"근거 ID — 근거 글"`** 형태로 나열합니다.
* **적용 규칙**: 사건에 지정된 `event.rules`의 모든 항목을 **`"규칙 ID — 규칙 글"`** 형태로 나열합니다. (규칙이 없으면 없음을 명시)
* **확인되지 않은 현재 상태 (`unknown_evidence`)**:
  * 사건 상태(`event.state`) 중 `unknown`인 항목을 접속·세션·기기별로 구분하여 원래 값과 함께 나열합니다:
    * 접속: `접속: 확인 불가(unknown)`
    * 세션: `세션: 확인 불가(unknown)`
    * 기기: `기기: 확인 불가(unknown)`
  * `unknown` 상태가 하나도 없으면 `없음`으로 표시합니다.
  * **어떤 경우에도 `unknown` 상태를 정상·안전·기준 충족으로 왜곡하거나 단정하지 않습니다.**
* **조치 제안 (`proposal_not_executed`)**:
  * AI 제안(`proposals`)이 비어 있고 `supportedActions`도 비어 있는 경우: *"원천이 지원하는 조치가 없어 제안이 없습니다 (정상). 연동 시스템이 지원하는 조치가 없습니다."* 안내.
  * AI 제안이 있는 경우: 각 조치와 이유(`action — reason`)를 나열하고, 반드시 *"사람 확인이 필요하며 실행되지 않았습니다 (미실행). 자동 실행 버튼은 제공되지 않으며 실제 원천 조치는 승인 후 집행되어야 합니다."* 문구를 명시합니다.
  * **실행 버튼(조치 집행 버튼)은 절대 생성하지 않습니다.**
* **설명 시각 및 보존 문구**: `checkedAt` 시각을 명시하고, 기록 보존 안내를 유지합니다.

## 3. 핵심 보안 원칙 및 설계 근거

1. **AI 설명은 '해석'이며 사실 판단의 기준이 아님**:
   * AI의 요약은 참고용이며, 최종적인 사실 판단은 원천 기록에 첨부된 근거(`evidence`)와 실제 상태(`state`)를 기준으로 이루어져야 합니다.
2. **`unknown` 상태 왜곡 방지 (보안 침묵/착시 차단)**:
   * 보안 시스템에서 상태 확인 불가(`unknown`)는 안전하다는 뜻이 아닙니다. 이를 정상이나 통과로 뭉개지 않고 명확히 사용자에게 확인 불가로 전달해야 합니다.
3. **제안과 실행의 엄격한 분리 (Human-in-the-Loop)**:
   * AI가 제안한 조치는 결코 자동으로 실행되어서는 안 되며, 사람이 원천 권한과 대상을 확인한 후 별도의 승인 절차를 거쳐야 합니다. 학생 화면에 실행 버튼을 두지 않음으로써 오작동 및 권한 없는 실행을 차단했습니다.
4. **DOM 보안 및 불변성 보장**:
   * 모든 텍스트 출력에 `textContent`만을 사용하여 HTML 인젝션(XSS) 취약점을 원천 차단했습니다.
   * 다른 사건 선택, 새로고침, 에러 발생 시 이전 설명 내용과 `data-student-explanation-event` 속성이 즉시 제거되어 잔류 데이터로 인한 혼선을 방지했습니다.

## 4. 검증 결과

* **문법 검사 (`npm run check`)**: `node --check student/extension.mjs` 검사 결과 문법 오류 없이 정상 통과.
* **단위 검증 (10개 시나리오 40개 항목 100% 통과)**:
  1. `status === 'error'` (사건 null): 안전한 오류 표시, 기록 보존 문구 확인, 속성 미부여 통과
  2. `status === 'error'` (사건 존재): 대상 사건 ID 표시, 무효 출력 안내 확인, 속성 미부여 통과
  3. `status === 'loading'`: 로딩 안내 확인, 속성 미부여 통과
  4. `event === null` (idle): 사건 선택 대기 안내 확인, 속성 미부여 통과
  5. 근거 부족 사건 (`evidence: []`): 설명 거부(근거 부족·입력 오류), 속성 미부여 통과
  6. 허위 실행 주장 (`executed: true`): 설명 거부, 속성 미부여 통과
  7. 근거 불일치 (`fake evidenceId`): 설명 거부, 속성 미부여 통과
  8. 정상 설명 수용 (`unknown` 상태 및 `supportedActions: []`): `data-student-explanation-event` 부여, 근거 바인딩, 규칙 바인딩, 기기 unknown 확인 불가 표기(정상/안전 단정 없음), 제안 없음 정상 안내, 버튼 미생성 확인 통과
  9. 정상 설명 수용 (제안 존재): 제안 조치·이유 표기, 사람 확인 필요 및 미실행 안내, 버튼 미생성 확인 통과
  10. 사건 전환 및 초기화 (reset): `data-student-explanation-event` 속성 제거 및 대기 상태 복귀 통과
