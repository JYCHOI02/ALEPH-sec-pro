# 17단계 작업 요약 (케셰브 보안 Agent)

이 문서는 보안 Agent **「케셰브」**의 17단계 **「앱 내부 AI 연결 상태 표시」**에서 구현한 기능과 핵심 보안 개념을 알기 쉽게 정리한 작업 기록입니다.

---

## 1. 전체 목표

앱 내부 AI 연결 점검 결과와 실제 보안 사건에 대한 AI 설명 실행을 명확히 구분하고, 점검 상태(`idle`, `loading`, `error`, `ok`)와 7대 오류 원인에 대한 안전한 안내를 제공하며, 실제 사건 설명의 기초 렌더러를 규격에 맞춰 안전하게 구현했습니다.

* **수정 파일**:
  1. `student/extension.mjs` 내 `renderAiConnection` (AI 연결 상태 표시 영역)
  2. `student/extension.mjs` 내 `renderExplanation` (AI 사건 설명 기초 표시 영역)
* **표시 위치**:
  * "보호 현황" 탭의 **[학생 AI 연결 상태]** 영역 (`renderAiConnection`)
  * "보안 기록" 탭의 **[학생 AI 사건 설명]** 영역 (`renderExplanation`)

---

## 2. 구현한 핵심 기능

### 1) AI 연결 점검 상태의 명확한 구분 (`renderAiConnection`)
* **점검 대기 (`idle`)**:
  * *"AI 연결 점검 전입니다. 설정값 존재는 이용 권한 확인이 아닙니다."* 문구 명시.
  * *"제공 영역의 「현재 API 연결 점검」 버튼을 눌러 점검을 시작하세요. (자동으로 점검하지 않습니다.)"* 안내.
  * 설정값(토큰/키)이 앱 내에 존재한다고 해서 실제 통신 및 권한이 검증된 것으로 오인하지 않도록 방지했습니다.
* **점검 중 (`loading`)**:
  * *"AI 모델 응답 점검 중… 모델 목록과 통신 상태를 확인하고 있습니다. 잠시만 기다려 주세요."* 상태 텍스트 안내.
* **점검 완료 (`ok`)**:
  * **수송 통신 (`transportChecked`)**: 통신 프로토콜 확인 완료 표시.
  * **인가 대상 (`audienceAuthorization`)**:
    * `'test'`인 경우: `시험 연결 점검(test) · 실제 게이트 수용 아님` (테스트 환경과 운영 게이트 구분)
    * `'verified'`인 경우: `앱 권한 확인 후 점검(verified)`
  * **응답 모델 수 (`modelCount`)**: 반드시 **`응답 모델 수`** 라벨로 정확한 개수를 명시 (`N개`).
  * **점검 시각 (`checkedAt`)**: 점검이 완료된 시각 표시.
  * **사건 설명 미실행 주의 문구**:
    * *"사건 설명은 아직 실행하지 않았습니다. 실제 사건 설명의 근거와 결과는 보안 기록에서 별도로 확인하세요."* 필수 명시.
    * 연결 점검 성공을 사건 설명 성공으로 오인하는 보안 착시를 원천 차단했습니다.
  * **수동 재점검 안내**:
    * *"다시 점검은 제공 영역의 「현재 API 연결 점검」 버튼을 직접 누르세요. (자동으로 다시 점검하지 않습니다.)"* 안내.
* **상태 초기화 및 이전 결과 잔류 방지**:
  * 점검 실패 후 재점검 성공 시 이전 에러가 지워지고 정상 결과만 렌더링됩니다.
  * `idle` 복귀 시 이전 성공/실패 결과가 남지 않고 초기 대기 상태로 복귀합니다.

### 2) 7대 원인별 안전한 오류 및 취소 안내 (`safe_ai_errors`)
* API 키, 비밀번호, 서버 내부 스택 트레이스 등 민감 정보 노출을 전면 차단하고, 안전하게 정제된 `error.code`와 `error.message`만 표시합니다.
* 오류 코드별로 사용자가 직접 취할 수 있는 조치 방법을 7대 원인에 맞춰 안내합니다:

| 원인 분류 | 대표 오류 코드 | 화면 안내 문구 |
|---|---|---|
| **1. 권한 준비 중·확인 불가** | `ON_AI_PROVISIONING_PENDING`, `AI_REQUEST_UNVERIFIED`, `ON_AI_AUTHORIZATION_CHANGED`, `SUBJECT_SCOPE_UNVERIFIED` | 보안 계정 승인 후 AI 권한이 준비 중이거나 대상 권한이 확인되지 않았습니다. 승인 상태를 확인한 뒤 다시 시도하세요. |
| **2. 인증 실패·접근 제한** | `WB_CLCO_AUTH_REQUIRED`, `WB_CLCO_ACCESS_BLOCKED` | AI 인증이 필요하거나 접근이 제한되었습니다. 워크벤치 연결 상태 및 인증을 확인하세요. |
| **3. 반 사용량·이용 한도** | `WB_CLCO_COHORT_BUDGET_EXHAUSTED`, `WB_CLCO_LIMIT_REACHED` | 반 전체 사용량 또는 이용 한도가 모두 소진되었습니다. 잠시 후 다시 시도하거나 운영진에 문의하세요. |
| **4. 이용 시간 아님** | `WB_CLCO_SESSION_CLOSED` | 현재는 AI 이용 가능 시간이 아닙니다. 수업 또는 실습 시간에 다시 시도하세요. |
| **5. 요청 제한·시간 초과·네트워크** | `WB_CLCO_RATE_LIMITED`, `WB_CLCO_TIMEOUT`, `REQUEST_TIMEOUT`, `ENGINE_TIMEOUT`, `TIMEOUT` | 요청이 제한되었거나 응답 시간이 초과되었습니다. 네트워크 상태를 확인하고 잠시 후 다시 시도하세요. |
| **6. 취소** | `WB_CLCO_CANCELLED`, `CANCELLED`, `REQUEST_CANCELLED` | AI 연결 점검 요청이 사용자에 의해 취소되었습니다. |
| **7. 모델 없음** | `MODEL_NOT_CONFIGURED`, `ON_AI_MODEL_LIST_EMPTY` | 사용 가능한 AI 모델이 구성되지 않았거나 목록이 비어 있습니다. |

### 3) AI 사건 설명 기초 구현 (`renderExplanation`)
* **정상 설명 수용 (`ok`)**:
  * 반드시 `explanation.status === 'ok'`이고 대상 사건이 존재할 때만 최상위 컨테이너에 **`data-student-explanation-event="<event.id>"`** 속성을 부여합니다.
  * 사건 ID(`사건 ID: <event.id>`)와 AI가 생성한 요약 텍스트(`explanation.data.summary`)를 표시합니다.
  * *"이 설명은 선택된 사건의 AI 분석 결과입니다. 제안은 자동 실행되지 않으며, 기록은 그대로 유지됩니다."* 안내를 함께 출력합니다.
* **설명 실패 (`error`)**:
  * **`data-student-explanation-event` 속성을 절대 부여하지 않습니다.** (실패를 성공으로 오인하는 루브릭 감점 방지)
  * 안전한 `error.code`와 `error.message`를 출력합니다.
  * *"기록은 그대로 유지됩니다. AI 연결이나 응답 문제는 과제 실패로 처리되지 않습니다."* 문구를 명시하여 원본 보안 기록의 불변성을 보장합니다.
* **설명 생성 중 (`loading`) 및 대기 (`idle`)**:
  * `data-student-explanation-event` 속성을 부여하지 않고, 각각 로딩 안내 또는 사건 선택 안내 문구를 표시합니다.

## 3. 핵심 보안 개념 및 확인 사항

### 1) 연결 점검과 사건 설명의 명확한 분리
* **연결 점검**: 서버 전용 키와 통신 채널이 살아있는지, 사용 가능한 모델이 몇 개인지 확인하는 기술적 통신 상태 점검입니다.
* **사건 설명**: 특정 보안 사건의 원천 기록과 근거를 읽고 분석 요약을 받아오는 실제 비즈니스 작업입니다.
* 연결 점검이 `ok` 되었다고 해서 사건 설명이 실행되었거나 성공한 것이 아니므로, UI에서 이를 혼동하지 않도록 안내하는 것이 필수적입니다.

### 2) 세 AI의 역할 구분
1. **워크벤치 수업용 AI**: 실습 안내, 과제 힌트 및 학습 지원을 제공하는 수업 도우미 AI.
2. **앱 내부 AI 설명 기능**: 학생 클라이언트 내부에서 보안 기록을 요약·해석하여 사람이 판단할 수 있도록 돕는 참고용 AI (자동 조치 실행 불가).
3. **ALEPH 과제 판정 AI**: 학생이 작성한 코드의 보안 규칙 준수 여부와 루브릭 통과를 기계적·의미적으로 검증하는 채점/판정 엔진.

### 3) DOM 보안 원칙
* `innerHTML`을 일체 사용하지 않고 `document.createElement`와 `textContent`를 사용해 XSS 취약점을 방지했습니다.
* 시크릿 키나 민감한 토큰 정보를 화면에 렌더링하지 않습니다.
